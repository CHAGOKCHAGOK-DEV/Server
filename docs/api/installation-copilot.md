# 앱 설치 및 부기장 프로필 API

앱 설치 인스턴스마다 Installation 하나와 Copilot 프로필 최대 하나를 사용합니다. 회원 계정이나 가족 계정은 사용하지 않습니다. 앱을 삭제하고 토큰을 잃으면 이전 설치의 데이터는 1차 MVP에서 복구할 수 없습니다.

## 설치 등록

`POST /api/v1/installations`는 인증 없이 호출하며 본문이 없습니다. 성공 시 HTTP 201로 `installationId`와 무작위 설치 토큰을 반환합니다. 원문 토큰은 이 응답에서만 제공하고 DB에는 SHA-256 해시만 저장합니다. 응답에는 `Cache-Control: no-store`가 적용됩니다.

```json
{
  "isSuccess": true,
  "code": "OK",
  "data": {
    "installationId": "11111111-1111-4111-8111-111111111111",
    "token": "<안전한 저장소에 보관할 불투명 토큰>"
  }
}
```

Android는 두 값을 안전한 저장소에 보관하고 이후 요청에 `X-Installation-Id: <UUID>`, `Authorization: Bearer <token>`을 함께 보냅니다. 토큰 원문을 로그, 분석 이벤트 또는 일반 설정 파일에 남기지 않습니다. 등록 재시도는 새 설치를 만듭니다. 응답을 잃었다면 기존 발급 토큰을 복구할 수 없으므로 새로 등록합니다. 등록은 서버 프로세스 기준 원격 주소당 한 시간에 20회로 제한하며 초과 시 HTTP 429 / `INSTALLATION_429`를 반환합니다. 프록시 뒤에서는 원격 주소가 프록시 주소로 보일 수 있으므로 실제 클라이언트별 제한은 신뢰된 진입 지점에도 설정해야 합니다.

`DELETE /api/v1/installations/me`는 인증된 설치 토큰을 즉시 폐기합니다. 폐기 후 같은 토큰으로 프로필 또는 주행 동기화 API에 접근할 수 없습니다. 토큰은 자동 만료하지 않으며 회전·재발급·재설치 후 복구는 1차 범위에 포함하지 않습니다.

## 부기장 프로필

모든 요청에 설치 인증 헤더가 필요합니다. 리소스는 인증된 설치의 프로필 하나이며 요청 본문에서 소유자 ID를 받지 않습니다.

| Method | 경로 | 결과 |
| --- | --- | --- |
| `POST` | `/api/v1/copilot` | 프로필 생성, HTTP 201. 이미 있으면 HTTP 409 / `COPILOT_409` |
| `GET` | `/api/v1/copilot` | 프로필 조회, 없으면 HTTP 404 / `COPILOT_404` |
| `PUT` | `/api/v1/copilot` | 기존 프로필 수정, 없으면 HTTP 404 / `COPILOT_404` |

생성·수정 본문은 같습니다.

```json
{
  "nickname": "은우",
  "ageGroup": "AGE_7_8",
  "missionIntensity": "NORMAL"
}
```

별명은 한글 완성형·영문·숫자 1~8자입니다. 연령대는 `AGE_5_6`, `AGE_7_8`, `AGE_9_10`이고, 강도는 `LOW`(5분), `NORMAL`(3분), `HIGH`(2분)입니다. 세 필드 모두 필수입니다. 수정해도 주행 기록은 삭제하거나 다른 설치로 옮기지 않습니다. 다른 설치의 토큰으로 현재 설치의 프로필을 읽거나 바꿀 수 없습니다.

## 운영 조건

운영 프로필은 설치 등록, 프로필, 주행 동기화 요청을 HTTPS에서만 받습니다. HTTP 요청은 `INSTALLATION_403`으로 거부합니다. 현재 EC2 배포는 80번 포트의 HTTP만 제공하므로 이 기능을 운영에서 사용하기 전에 TLS 종단과 신뢰된 프록시 설정이 필요합니다. TLS 프록시를 사용한다면 앱이 `request.isSecure()`를 올바르게 인식하도록 프록시와 서버 사이의 전달 헤더를 신뢰된 프록시에서만 처리해야 합니다. 현재 배포 방식에서 HTTPS가 준비되기 전에는 이 버전을 운영에 배포하지 않습니다.
